# 设计契约（Design Contract）—— 全队产出准线

**适用范围：全团队（强制准线）。** 任何产出 UI / 交互 / 视觉的场合都必须满足本契约——
包括产品、研发用 Coding Agent 直接开发的 Demo、原型、活动页。目标：**产出可直接进协作，
不需要设计侧重构**。不满足 = 未完成。

## 1. 设计系统优先

1. 组件、间距、字号、色板一律取自设计系统（`DESIGN_SYSTEM_URL`）；确需新增：先查重 →
   记录偏离理由 → 反馈设计系统维护清单。
2. 色彩对比度 ≥ 4.5:1；不得仅靠颜色传达信息（配图标/文字）。

## 2. 状态覆盖（五类必有，缺一打回）

空 / 加载 / 错误（含重试入口）/ 无权限 / 极端长度（超长文本、零数据、慢网络）。

## 3. 交互与无障碍

- 可聚焦元素有可见焦点态；触达区域 ≥ 44px；图标有替代文本；动效 ≤ 300ms 且可降级。
- 错误提示 = 发生了什么 + 怎么办；破坏性操作二次确认；用户可撤销/退出。

## 4. 文案

- 按钮用动词（「保存」「提交」）；一处一个 CTA；术语与 `docs/context/glossary.md` 一致。
- 文案是设计的一部分：空态、错误提示必须有终稿，不留给实现方即兴。

## 5. 响应式

- 断点差异逐条说明；禁止「同移动端」一句话交付。

## 6. 免重构自检（进入协作前）

| 检查项 | 方式 |
|---|---|
| 设计系统一致性、状态覆盖、无障碍四件套 | 调用 `design-reviewer` Agent 自检 |
| 文案终稿与术语一致 | 对照 glossary 人工确认 |
| 与需求 AC 对应（每个界面状态有出处） | 对照需求卡片 |

全部 ✅ 才算「可直接进协作」；`design-reviewer` 的阻断项必须清零。
