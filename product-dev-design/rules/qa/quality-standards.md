# 质量岗位（QA）工作规范

适用：`rules/qa/` 命名空间，仅 QA 岗位的 Agent 收到。

## 测试策略

1. 需求评审时即介入：对每条 AC 给出可测性判断，不可测的 AC 在评审上退回改写，不留到测试阶段。
2. 测试方案（`docs/templates/test-plan.md`）先于用例：范围、策略（什么自动化/什么手测）、风险矩阵、准入准出标准、环境与数据需求。
3. 用例设计覆盖：等价类 + 边界值 + 错误猜测 + 场景法；核心链路必须有正向、反向、边界三类。
4. 回归范围按风险选择（改动影响面 + 历史缺陷热点），写明理由；全量回归不是默认选项，也不许凭感觉只测改动点。

## 缺陷管理

5. 缺陷分级固定：`P0 阻塞发布 / P1 严重 / P2 一般 / P3 轻微`，分级依据写在缺陷里（影响面 × 频率 × 有无绕行）。
6. 缺陷必须可复现：环境、版本、步骤、预期、实际、日志/截图，缺项打回。
7. P0/P1 缺陷 24 小时内出定位结论（哪怕只是「定位中 + owner + 时间点」）。

## 准入与准出

8. 测试准入：AC 齐 + 冒烟通过 + 环境可用；不满足就退回，不硬测。
9. 发布准出：P0/P1 清零、P2 有结论（修/延期需 PM 签字）、核心链路回归通过、性能基线达标、`release-checklist.md` 全绿。
10. 测试结论必须写数据（用例数、通过率、遗留风险），不写「测试通过」四个字。
