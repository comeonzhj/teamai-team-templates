# 上下文维护规则（强制，Agent 必读）

团队的上下文不是写一次就完的文档，而是持续维护的运行状态。你的每次会话都要维护它。

## 什么时候必须更新 `docs/context/current-status.md`

- 一个阶段的产出物交付或通过评审时（更新「当前阶段 / 进行中事项」）
- 出现阻塞或解除阻塞时（更新「阻塞」）
- 排期、范围、负责人发生变化时
- 上线、回滚、事故处理结束时

## 什么时候必须更新 `docs/context/decisions.md`

- 做出一个会约束后续工作的选择（技术选型、方案取舍、范围裁剪、口径定义）
- 推翻或修订了已有决策（**不要改写旧记录**：新增一条记录说明被取代）

## 书写格式

- 状态文档：短句、带日期、带负责人。状态用词固定为 `未开始 / 进行中 / 阻塞 / 待验收 / 已完成`。
- 决策记录：编号递增（`D-001`…），字段见 `docs/context/decisions.md` 的模板段。
- 只写结论和影响，不写讨论过程；过程留在 PR / 评审评论里。
- 数字必须带口径与来源（如「转化率 3.2%，口径：近 7 日全量新用户，来源：PRODUCT_ANALYTICS_URL」）。

## 边界

- 不在 `docs/` 里写入个人隐私、凭据、未公开的商业敏感数字（见 rules/ai-usage-policy.md）。
- 不确定该写在哪时：状态进 current-status，选择进 decisions，其余进对应阶段文档或模板产物。
