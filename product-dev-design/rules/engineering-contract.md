# 工程契约（Engineering Contract）—— 任何代码产出的准入基线

**适用范围：全团队（强制准线）。** 研发的代码、产品/设计用 Coding Agent 写的 Demo 与
迭代、脚本与工具，一律适用。目标：**产出可直接进协作，不需要研发侧重构**。

## 1. 项目约定优先

1. **已有项目**：先读项目的 `AGENTS.md` / `CLAUDE.md`、目录结构、lint 与测试命令、CI 配置、
   现有模块边界——遵循既有约定；要立新约定先写 `docs/context/decisions.md`。
2. **新建 Demo**：目录、命名、分层参照团队约定；UI 组件复用设计系统的代码实现
   （见 `design-contract.md`）。

## 2. 代码质量基线

- 类型安全：禁 `any`、裸断言、吞异常；错误路径显式处理。
- 密钥零落地：用 `teamai env exec --` 或本地 `.env`（且 `.env` 不入库）。
- 公共函数写文档注释；TODO 必带 issue 链接；无调试代码、无注释掉的死代码入主干。

## 3. 提交与版本

- Conventional Commits（`feat:/fix:/chore:/docs:/refactor:/test:`），一个提交只做一件事；
  AI 参与生成的代码在提交说明注明；不夹带无关改动。

## 4. 测试基线

- 新逻辑必带测试；修 bug 先写复现测试。
- 核心路径覆盖正向 / 反向 / 边界三类；测试可重复执行、无隐式网络/时间依赖（或显式标记）。

## 5. 可观测与回滚

- 关键路径有日志与错误上报；新功能有开关或明确回滚路径；变更说明写清影响面。

## 6. 性能与安全预算

- 核心接口 P95 < 300ms（或沿用项目既定预算，写明出处）；输入校验、权限校验、依赖最小化。

## 7. 免重构自检（进入协作前）

| 检查项 | 方式 |
|---|---|
| 正确性、测试、AC 覆盖、可回滚 | 调用 `code-reviewer` Agent，阻断项清零 |
| lint / 类型检查 / 测试 | 项目命令全绿（记录执行结果） |
| 项目约定一致 | 对照项目 AGENTS.md/CI 清单 |
