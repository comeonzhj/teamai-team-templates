# 阶段交接包（handoff）

交接不是「文件发了」，而是让下游**不需要追问**即可开工。

## 交接包标准结构

```text
<handoff-包>/
  00-summary.md        # 一页摘要：目标、范围、不做什么、关键决策链接、风险
  01-<上游产出物>       # PRD / 设计交付包 / 技术方案 / 测试报告（套用 templates/ 模板）
  02-open-questions.md # 未决问题 + 建议方案 + 需要谁拍板
  03-checklist.md      # 下游开工前自检清单（见下）
```

## 各阶段交接要点

- **需求 → 设计**：问题定义、AC、成功指标、约束（平台/性能/合规）、已否决方向。
- **设计 → 研发**：标注稿、状态覆盖、交互/动效说明、设计走查结论、文案终稿。
- **研发 → 测试**：技术方案、影响面分析、变更清单、开关/灰度说明、自测报告、已知风险。
- **测试 → 发布**：测试报告（数据）、遗留缺陷清单及处置、回归范围与结果、发布建议。
- **发布 → 复盘**：发布记录、监控数据、事故/回滚记录、指标对比。

## 发出前自检（不合格不发）

1. 00-summary 一页读完能明白「做什么、为什么、边界在哪」。
2. 每条 AC / 每个设计态 / 每个接口变更都有对应落点。
3. 所有链接可访问，所有数字带口径与来源。
4. 未决问题写明 owner 和期限，不写「待讨论」。
5. 同步更新 `context/current-status.md` 的阶段状态。

## 收到交接包时

先跑 `03-checklist.md` 逐项核对；缺项打回补齐（列清单，不口头追问两次）。核对通过后在 `current-status.md` 认领下一阶段事项。
