# 质量保障工作流（QA）

## 1. 需求阶段介入（左移）

- 对每条 AC 做可测性评审：给不出验证方法的 AC 退回改写。
- 列出测试风险（改动面大 / 历史缺陷热点 / 数据敏感 / 新技术栈），进入测试方案的风险矩阵。

## 2. 测试方案

按 `docs/templates/test-plan.md`：范围（测什么/不测什么）、策略（自动化 / 手测 / 探索性测试的分工）、风险矩阵、准入准出标准、环境与数据需求、排期与人力。

## 3. 用例设计

- 方法：等价类划分 + 边界值 + 错误猜测 + 场景法（用户旅程串联）。
- 核心链路三件套：正向、反向、边界。每条用例写明前置、步骤、预期、优先级（P0 冒烟 / P1 核心 / P2 一般 / P3 边缘）。
- 自动化优先覆盖 P0/P1 的稳定回归路径；探索性测试保留 20% 时间给脚本外的意外。

## 4. 执行与缺陷

- 缺陷分级依据「影响面 × 频率 × 有无绕行」：`P0 阻塞发布 / P1 严重 / P2 一般 / P3 轻微`。
- 缺陷必须可复现（环境、版本、步骤、预期、实际、日志）；P0/P1 24 小时内给定位结论。
- 每日测试结论写数据：执行数、通过率、新增缺陷、遗留缺陷、风险。

## 5. 准出与发布

- 准出：P0/P1 清零；P2 有处置结论（修 / 延期需 PM 签字）；核心链路回归通过；性能基线达标；`release-checklist.md` 全绿。
- 发布时陪跑：盯错误率与核心指标 30 分钟；异常立即建议回滚。

## 6. 复盘与度量

- 缺陷逃逸率（线上缺陷 / 测试阶段发现总数）与用例有效性进复盘。
- 每次复盘沉淀 1-2 条可复用经验到团队知识库（`teamai contribute`）。
