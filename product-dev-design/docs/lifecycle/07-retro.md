# 阶段 7 · 复盘与沉淀（Retro / Learning）

> 主责：全员 ｜ 触发：版本上线后 7 天内 / 事故后 48 小时内
> 产出物流向：→ 回到阶段 1（新的改进需求）+ 团队知识库

## 目标

把「发生了什么」变成「下次怎么办」和「团队已知的经验」，而不是流水账。

## 进入条件

- 上线后有 ≥ 7 天数据，或事故已有初步定位。

## 关键动作

1. **数据回顾**：对照需求卡片的成功指标（口径 + 来源），写「预期 vs 实际」。
2. **过程回顾**：时间线（计划 vs 实际）、质量指标（缺陷逃逸率、返工次数）、协作摩擦点。
3. **根因分析**：对每个显著问题用 5 Whys 追到流程/机制层，不停在「某人疏忽」。
4. **改进项**：每条 = 动作 + owner + 期限 + 验证方式；不超过 5 条，宁缺毋滥。
5. **知识沉淀**：可复用经验用 `teamai contribute` 沉淀进团队知识库；踩坑教训写进对应阶段文档或规则（走 `decisions.md` 留痕）。

## 产出物

- 复盘报告（`../templates/retro.md`）
- 改进项（写入 `current-status.md` 的「进行中」跟踪）
- 至少 1 条团队知识沉淀（`teamai contribute` / `teamai share`）

## DoD（完成定义）

- [ ] 成功指标有数据结论（含口径与来源）
- [ ] 每条显著问题有根因与改进项
- [ ] 改进项全部有 owner 与期限
- [ ] 知识已沉淀进团队知识库

## 交接

→ 阶段 1：改进项中需要排期的，按需求卡片立项
→ 全队：复盘结论在周会同步 5 分钟

## 常见坑

- 复盘变成批斗会或流水账——只谈事实与机制。
- 改进项没有 owner 和期限，等于没做。
- 教训只留在复盘文档里，没进规则/阶段文档，下次照犯。
