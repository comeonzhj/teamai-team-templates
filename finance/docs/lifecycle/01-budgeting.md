# 环节 1 · 预算与滚动预测（Budgeting & Forecast）

> 主责：fpna ｜ 协作：全员（部门申报）｜ 产出 → 各环节的额度基准

## 目标

把经营目标翻译成**有假设、有依据、可追踪**的财务计划。

## 进入条件

- 公司年度目标已定（收入/利润/现金流）；预算日历（`../context/close-calendar.md`）确认。

## 关键动作

1. **假设集**：量价（分产品/渠道）、人数与人效、费用率、资本开支；每项写依据。
2. **自上而下拆目标** + **自下而上收部门申报**；差异在评审会收敛（差异原因要落档）。
3. **编制**（`../templates/budget-template.md`）：三大表（利润/现金流/资产负债关键项）+ 部门费用预算。
4. **敏感性分析**：关键假设 ±10% 的影响（≥ 3 情景）。
5. **评审与批准**：v1 编制 → v2 评审 → v3 批准下达；下达后变更走预算调整（`decisions.md`）。
6. **滚动预测**：月度更新，只调已知变化 + 假设变化，逐项说明原因。

## 产出物

- 批准版预算（版本号）+ 假设说明 + 敏感性分析 + 预算科目映射

## DoD

- [ ] 每项假设可追溯（历史/合同/市场）
- [ ] 三大表勾稽平衡
- [ ] 上下差异已收敛并留痕
- [ ] 批准与下达留档；部门额度已下发

## 交接

→ 各部门/核算（环节 2）：部门预算额度 + 费用标准 + 科目映射
→ 分析（环节 5）：预算作为对比基期（口径一致）

## 常见坑

- 「去年 × 1.1」无假设预算，差异分析无从谈起。
- 只编利润表不编现金流，账面赚钱现金紧张。
- 预算下达后随意调整，失去基准意义。
