# 环节 6 · 绩效评定（Performance）

> 主责：hrbp ｜ 周期：季/半年（按 `../context/performance-framework.md`）

## 目标

让评定**有据可查、尺度一致、能驱动改进**，而不是打分仪式。

## 进入条件

- 目标卡已设定（权重与评分标准期初写死）；期中回顾有记录。

## 关键动作

1. **评定**：对照期初目标 + `../context/competency-model.md` 逐条举证；
   **写不出证据的维度不打分**。等级口径见 `performance-framework.md`。
2. **偏差自检**：近因效应、光环效应、趋中/宽严、相似性偏见。
3. **校准会**：经理陈述证据 → 交叉质询（「证据是什么」）→ 对齐尺度 → 定案；
   偏离参考分布必须说明理由；调整记录留档可复核。
4. **反馈面谈**（SBI：情境-行为-影响）：事实 → 影响 → 听解释 → 共识 → 改进/发展计划 → 支持资源；
   书面确认（结论 + 行动），双方留档。
5. **后续**：S/A 激励与 IDP；C 进入 PIP（标准、支持、期限、检查点、可能结果）。
6. **申诉**：24h 响应、保密、按「标准 + 证据」复核、书面告知。

## 产出物

- 绩效评定表（`../templates/performance-review.md`）+ 校准记录 + 面谈记录

## DoD

- [ ] 每个等级有证据支撑，可被复核
- [ ] 校准会已开，分布与个案调整有理由
- [ ] 反馈面谈完成并书面确认
- [ ] PIP/激励动作有 owner 与时间
- [ ] `current-status.md` 更新（聚合口径，不写姓名对应）

## 交接

→ 人才培养（环节 7）：发展类结论进 IDP
→ hr-ops：激励/调薪动作进流程

## 常见坑

- 期末凭印象打分，期中无记录。
- 校准会变成「谁嗓门大」。
- 负面反馈攒到期末突然袭击。
