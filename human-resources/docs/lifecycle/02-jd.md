# 环节 2 · JD 与雇主品牌（Job Description）

> 主责：recruiter ｜ 产出 → 环节 3 上架渠道

## 目标

写出**吸引对的人、劝退不对的人**的 JD，并合规无风险。

## 进入条件

- 需求单已批准，成功画像与必备项明确（环节 1 DoD）。

## 关键动作

1. **结构**（`../templates/jd-template.md`）：
   - 岗位使命一句话（这个岗位存在的意义）
   - 职责 ≤ 6 条：动词开头 + 对象 + 可衡量结果（「负责 X 的 Y，达成 Z」）
   - 要求分「必备（≤ 3）/ 加分」；写「做过什么、达到什么程度」，不写「精通」
   - 薪酬范围（能给就写）、团队与业务介绍（具体，不堆形容词）
2. **去偏语言**：去掉性别化词汇（「技术大牛」「抗压」换成具体场景）；
   合规自查（`rules/fairness-compliance.md`：无年龄/性别/婚育/户籍限制）。
3. **关键词**：岗位搜索词覆盖（标题别自造词：写「后端工程师」不写「技术艺术家」）。
4. **会签**：用人经理确认职责与要求；hr-lead 确认合规与薪酬带宽。
5. **上架**：按渠道策略发布（`JOB_BOARD_URL` / 内推 / 社区）；JD 版本号管理。

## 产出物

- JD（终版，带版本号）+ 渠道上架记录

## DoD

- [ ] 使命一句话可读；职责 ≤ 6 条可衡量
- [ ] 必备 ≤ 3、加分不作淘汰依据
- [ ] 合规自查通过（无歧视性表述）
- [ ] 用人经理与 hr-lead 双签

## 交接

→ 渠道与筛选（环节 3）：JD + 目标画像 + 渠道计划

## 常见坑

- 职责写成部门职责清单，看不出这个岗位做什么。
- 要求 10 条必备，把 P6 写成 P7。
- 「抗压能力强」「良好的沟通」这类不可测空话。
