# 环节 1 · 人力需求与岗位规划（Workforce Planning）

> 主责：hrbp + recruiter ｜ 产出 → 环节 2 JD

## 目标

把业务目标翻译成**有编制、有标准、有节奏**的人力需求。

## 进入条件

- 业务方给出目标与期望到岗时间（可以粗）。

## 关键动作

1. **需求澄清（intake）**：为什么招（业务目标）、招来做什么（成功画像）、必备项 ≤ 3、
   加分项、淘汰线、薪酬带宽、面试官。
2. **编制与预算校验**：HC 是否在编制内、预算是否覆盖（薪酬 + 招聘成本）；冻结期走特批。
3. **岗位定位**：职级（`../context/competency-model.md`）、岗位族、内外部渠道策略。
4. **风险预判**：市场供给、竞对、薪酬竞争力、周期风险；写明 Plan B（内调/外包/推迟）。
5. **批准**：需求单（`../templates/hiring-request.md`）走审批；结论进 `../context/decisions.md`。

## 产出物

- 招聘需求单 + intake 纪要（成功画像、必备项、淘汰线）

## DoD

- [ ] HC/预算/薪酬带宽合规且已批准
- [ ] 成功画像具体（12 个月做得好是什么样）
- [ ] 必备项 ≤ 3 且可验证
- [ ] 面试官与时间窗确认
- [ ] 已进 `current-status.md`（岗位代号 + 状态）

## 交接

→ 招聘（环节 2）：需求单 + intake 纪要（缺项可退回）

## 常见坑

- 「要一个全能的人」——必备项一堆，实际招不到。
- 没定淘汰线，筛到后面标准漂移。
- 冻结期偷偷招——合规与信任双输。
