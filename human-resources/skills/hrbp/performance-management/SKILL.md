# 绩效管理工作流（HRBP）

## 1. 目标设定

- SMART：具体、可衡量、有期初基线、有验收方式、有期限；与团队目标对齐（OKR 关联）。
- 权重与评分标准**期初写死**（如「指标 A 40%：达成 ≥ 100% 得 5 分…」），避免期末争议。
- 期中调整目标必须双方确认并留痕（进 `decisions.md` 或绩效系统记录）。

## 2. 期中回顾

- 至少季度一次：进展、障碍、支持、目标是否仍成立；有负面信号必须当场给出，不攒到期末。
- 记录用 SBI（情境-行为-影响），为评定积累证据。

## 3. 评定与校准

- **先证据后结论**：对照期初目标与 `competency-model.md` 逐条举证；写不出证据的维度不打分。
- 校准会（calibration）必开：跨团队对齐尺度；个案调整必须写理由；输出分布结论与调整记录。
- 常见偏差自检：近因效应、光环效应、趋中/宽严、相似性偏见。

## 4. 反馈面谈

- 结构：事实（SBI）→ 影响 → 听对方解释 → 共识结论 → 改进/发展计划 → 支持资源。
- 负面反馈给明确的改进标准与检查点；优秀反馈也给具体证据，不空夸。
- 面谈后书面确认（结论 + 行动），双方留档。

## 5. PIP 与申诉

- PIP：问题事实、期望标准、支持措施、期限（通常 30-90 天）、检查点、可能结果；全程书面。
- 申诉：24 小时内响应、保密、可复核（标准 + 证据），结论书面告知（`rules/fairness-compliance.md`）。
